About me

A developer who cares how a site actually feels to use.

I’m Mohamed Bangura, a frontend developer based in Sierra Leone and an Information Technology student at IPAM. My work sits where design intention meets real browser behaviour — where a layout has to hold up on a 320 px phone, on a cheap Android tablet, and on a wide desktop monitor, without losing its character.

I build complete front-end experiences: semantic HTML structure, CSS systems that scale, and JavaScript for the interactions that make a site feel considered. I care about the unglamorous parts too — keyboard navigation, contrast, image weight, and pages that load quickly on an unreliable connection.

I’m comfortable taking a project from a rough idea and a folder of notes all the way to a deployed, hand-over-ready site, and I’m direct about what is realistic for a given budget and timeline.

How I work

Principles I hold to

  • Mobile-first, not mobile-shrunk

    Layouts are designed for a phone first, then expanded — not compressed down from a desktop grid.

  • Speed is a design decision

    Optimised images, modern formats, minimal JavaScript. Performance is part of the build, not an afterthought.

  • Accessible by default

    Semantic markup, real focus states, keyboard support and reduced-motion handling from the first component.

  • Clean, maintainable code

    Organised CSS custom properties, commented JavaScript and semantic HTML that another developer can pick up.

Process

How a project actually runs

The same five steps on every build, so you always know what happens next and what I need from you.

  1. 01

    Discovery

    We talk through the business, the audience and what the site needs to achieve. I ask what visitors should be able to do, and what currently gets in the way.

  2. 02

    Planning

    Page structure, content outline, features and scope are agreed in writing, with a fixed quote against that scope.

  3. 03

    Design & build

    Mobile-first layouts, semantic markup and the agreed interactions, built progressively so you can review real pages rather than mock-ups.

  4. 04

    Testing & refinement

    Checked across real screen sizes, keyboards and form flows. Layout issues, spacing and contrast are corrected before anything launches.

  5. 05

    Delivery

    Deployment, SEO configuration and a walkthrough of the code, so the site stays editable after handover.

  6. +

    After launch

    I’m available for updates, fixes and further pages. Scope and cost for anything beyond the agreed brief are confirmed before work starts.

Timelines and revision allowances are agreed per project before work begins — I don’t publish fixed numbers that don’t apply to your build.
