About me

A developer who cares how a site actually feels to use.

I’m Mohamed Bangura, a frontend web developer based in Sierra Leone and an Information Technology student at IPAM. My work sits where design intention meets real browser behaviour — where a layout has to hold up on a 320 px phone, on an inexpensive Android tablet, and on a wide desktop monitor, without losing its character.

I build complete front-end experiences: semantic HTML structure, CSS systems that scale, and JavaScript for the interactions that make a site feel considered. I care about the unglamorous parts too — keyboard navigation, contrast, image weight, and pages that load quickly on an unreliable connection.

I’m always willing to learn. Browser behaviour, performance work and accessibility keep pulling me deeper, and I’d rather spend a week getting a detail right than ship something I can’t defend. I’m comfortable taking a project from a rough idea and a folder of notes all the way to a deployed, hand-over-ready site.

How I work

Principles I hold to

  1. Mobile-first, not mobile-shrunk

    Layouts are designed for a phone first, then expanded — not compressed down from a desktop grid.

  2. Speed is a design decision

    Optimised images, modern formats, minimal JavaScript. Performance is part of the build, not an afterthought.

  3. Accessible by default

    Semantic markup, real focus states, keyboard support and reduced-motion handling from the first component.

  4. Clean, maintainable code

    Organised CSS custom properties, readable JavaScript and semantic HTML another developer can pick up.

Process

How a project actually runs

The same four steps on every build, so you always know what happens next and what I need from you.

  1. 01

    Discovery

    We talk through the business, the audience and what the site needs to achieve. I ask what visitors should be able to do, and what currently gets in the way.

  2. 02

    Design

    Page structure, content outline and visual direction are agreed in writing, with a fixed quote against that scope — so the layout is decided before it is built.

  3. 03

    Build

    Mobile-first layouts, semantic markup and the agreed interactions, built progressively so you can review real pages rather than mock-ups.

  4. 04

    Launch

    Checked across real screen sizes, keyboards and form flows, then deployed with SEO configuration and a walkthrough of the code so the site stays editable after handover.
