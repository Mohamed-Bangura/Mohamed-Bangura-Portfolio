Case study 03 · Education

Johnson’s Academy

A website for a digital skills training provider. Six service areas have to be genuinely distinguishable from one another — and a parent or student comparing courses on a phone has to be able to tell them apart at a glance.

  • HTML5
  • CSS3
  • JavaScript
  • WebP
  • JSON-LD

Project overview

Johnson’s Academy is a digital skills training and digital services provider. The site is four content pages — home, about, services and contact — plus a custom 404, built as a static site with a single stylesheet and a single script.

The site is deployed and publicly viewable, with the source available and deployment configuration for both Vercel and Netlify.

Purpose and intended audience

The audience is a prospective student or a parent looking for practical, job-relevant digital training, and a small business owner looking for the same skills delivered as a service. They are comparing options, and frequently doing it on an inexpensive phone.

  • Six service areas, kept visibly distinct — graphic design, video editing, social media management, Facebook Ads, Instagram Ads and digital marketing. Each has its own card, icon and description so none of them blur together.
  • Portfolio imagery per service, so a visitor can see the kind of work each course produces rather than reading a description and guessing.
  • A single FAQ section to answer the questions a student actually asks — format, duration, prerequisites — without a phone call.
  • An about page with the learning process, which is what distinguishes a training provider from a list of services.
  • A contact form with a map, so the enquiry route and the location are on the same page.

My role and responsibilities

I built the front end for PP Studio Agency: page structure, the design system, responsive layout across four pages, the JavaScript interactions, form validation, the SEO configuration and the deployment setup.

Technical approach

  • One stylesheet, organised by concern — the design system, layout and components live together in style.css, using CSS custom properties for the type scale, colour and spacing.
  • Typeface pairing of Sora for headings and Manrope for body text, giving headings a distinct voice without needing more than two families.
  • One script file — script.js contains navigation, the FAQ, form validation and scroll effects together, so the behaviour of a page can be read in one place.
  • IntersectionObserver reveals rather than scroll handlers, keeping scroll smooth on low-powered Android devices.
  • WebP with PNG fallbacks — every photograph ships in a modern format with a widely supported alternative alongside it.
  • Deploy-anywhere configuration. The repository includes a Vercel config and a Netlify config, so the same static output runs on either host with no build step.

Key features and design decisions

  • Single-open FAQ accordion. Opening one answer closes the others, so the section never turns into an unpredictable wall of open panels. Each control carries the correct ARIA state.
  • Hamburger navigation with smooth transitions for the mobile layout.
  • Scroll-to-top control that appears only after the visitor has moved down the page.
  • IntersectionObserver fade-ins across the content sections.
  • prefers-reduced-motion respected throughout — visitors who ask their system to reduce motion get a static page, not an animated one.
  • Client-side form validation with an async submit and clear pending, success and failure states, so a student knows whether their enquiry actually sent.
  • SEO on every page — unique meta descriptions, Open Graph and Twitter cards, JSON-LD structured data, sitemap.xml and robots.txt, all pointing at the correct domain.
  • A real 404 page, so a mistyped or retired link lands somewhere useful instead of a browser error.
  • Semantic HTML with ARIA labelling throughout, including a skip-to-content link and visible keyboard focus states.

Responsive behaviour

The service grid is the critical piece: six items have to stay readable rather than shrinking into two cramped columns. It steps down from three columns to two to one, and the card content reflows with it. The hamburger menu replaces the horizontal bar below the tablet breakpoint, and every page — including the pricing-equivalent services detail and the FAQ — stays usable at 320 px without horizontal scrolling.

The finished project

Four pages plus a 404, a working enquiry path, an accessible FAQ, and a reduced-motion path for visitors who need one. Deployed, live, and open for inspection.
